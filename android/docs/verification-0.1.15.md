# Android 0.1.15 verification

Scope: remove the Android in-app updater at the user's request and retain the artwork action fixes. Windows updater, provider logic, recommendation ranking, profile format and signing identity are unchanged.

Removed AppUpdates, UpdatesUi, UpdateInstallRequest, their debug probe/tests, background startup/foreground checks, observer lifecycle, update arrows/settings route, APK downloader/installer, update FileProvider and REQUEST_INSTALL_PACKAGES. About DART retains an ordinary HTTPS release link. Old saved Updates routes normalize to the settings index; profile flush onStop and browsing cleanup remain intact. The static update.json is only a final migration descriptor for installed 0.1.14 clients; the new APK has no reader for it.

Artwork actions are Like, Bookmark, Download original and Open source. The redundant Original publication row is removed for all attribution preferences. Original URL metadata is preserved, and selecting Original link applies it to the source action. Native UI checks in an owned hidden API35 emulator confirm action order, persisted likes/bookmarks, original URL preservation, an actual ACTION_VIEW intent to the chosen neutral original URL, and a compact 320dp layout with 130% font. The physical phone and personal profile are not controlled.

Verified on 2026-11-02 from source c6ba650159fea27e72f5e3209c88c7ded1fa5474. A clean debug build preceded the signed release build to avoid stale deleted classes. All 260 remaining unit tests passed; release lint reported 0 errors and 28 warnings. Version name is 0.1.15, version code is 17 so it also upgrades the earlier unpublished code-16 candidate.

The signed APK is 2,169,986 bytes, SHA-256 d3f0a2c16c1114026aeb3c67de62600c1b5136475263ef5f227b9276f152537c. APK signature schemes v2/v3 verify with the existing certificate SHA-256 b97a808c1adcfa9b0489b04b09848f8638eb6df276d259f044d58f1fd01fcf5d. Manifest inspection confirms only INTERNET and ACCESS_NETWORK_STATE as Android platform permissions, plus AndroidX's application-specific signature permission. REQUEST_INSTALL_PACKAGES and the update FileProvider are absent. Both DEX files were inspected: no AppUpdates, UpdatesUi, UpdateInstallRequest or UpdaterChecks classes, updater thread name or update-download directory remains. AndroidX Startup's initialization provider remains unrelated to APK installation.

A hidden owned API35 ArtCatalogQA emulator, separate user 10, received a neutral profile through the real document picker and import-consent dialog. Installing this signed APK directly over signed 0.1.14 succeeded. The native profile page retained one like and one bookmark; their full persisted records matched before/after, as did followed/hidden authors, favorite tags and viewed identities. Those other test collections were empty. Settings no longer shows Updates. About displays 0.1.15 and the manual releases link; tapping it produced ACTION_VIEW to https://github.com/4ek1st/DART/releases?q=android-v&expanded=true in the external browser. No AndroidRuntime error was observed during this smoke test.

Published as https://github.com/4ek1st/DART/releases/tag/android-v0.1.15 with --latest=false. The APK and checksum were downloaded from that release and verified against the local hash, GitHub asset digest, size and existing signing certificate. The Windows latest release remained v0.2.56. The legacy static descriptor is advanced only after published-asset verification; it allows already-installed updater versions to reach the final manual-update build. The new APK contains no code that reads that descriptor.

The Play Protect warning reported for 0.1.14 remains an external classification. Removal of the updater is verified locally; successful installation in the isolated emulator and signature checks do not establish that Google has cleared its verdict. No external APK scan or Google appeal has been submitted by this work.
